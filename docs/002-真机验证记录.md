### 已知限制（本轮产物级）

| 项 | 事实 | 影响 | 处置 |
|---|---|---|---|
| 16 KB 页对齐 | bring-up 的 `libnode.so` 是 **4 KB 对齐**（`min LOAD align=0x1000`） | 在本机（4 KB 页）**能跑**；但 16 KB 页设备与 Play 上架不合格 | 自建 Node 24 时加 `LDFLAGS='-Wl,-z,max-page-size=16384'`（规划附录 D）；门禁 ⑧ 保留为硬失败，`--allow-page-align-4k` 只是显式放行 |
| 运行时版本 | **Node 18.20.4**（EOL），非目标形态 | 与「自建 24.x」计划不符 | `runtime.lock.json` 里标 `tier: 🔶 bring-up`；自建链落地后替换 `active` |
| `libc++_shared.so` | `libnode.so` 的 `DT_NEEDED` **确实需要它**（P0-5 的第一个硬结论） | 缺它 ⇒ `dlopen` 直接失败 | `node-runtime` AAR 单点供给（`jniLibs/arm64-v8a/libc++_shared.so`，来自 NDK r27c） |

### 构建排障（留给后来者）

| 症状 | 根因 | 修法 |
|---|---|---|
| `Cannot add extension with name 'kotlin'` | AGP 9 内置 Kotlin 与 KGP 同时注册 `kotlin` extension | 移除 `org.jetbrains.kotlin.android`（用 AGP 内置 Kotlin）；或用 `android.builtInKotlin=false` + 与 AGP 9 兼容的 KGP（2.2.x 不兼容） |
| `LibraryExtensionImpl$AgpDecorated_Decorated cannot be cast to BaseExtension` | KGP 2.2.10 不认识 AGP 9 的新 DSL | 同上 |
| `DefaultAndroidLibrarySourceSet cannot be cast to AndroidLibrarySourceSet` | `sourceSets.getByName("main"){ jniLibs.srcDir(...) }` 在 AGP 9 Kotlin DSL 里的类型不匹配 | 让生成物落到默认 source set（`src/main/jniLibs`、`src/main/assets`） |
| `spawnSync` 的 `退出码 null` | Windows 上 NDK 的交叉 clang 是 `.cmd`，Node 18+ 禁止直接 spawn | `tools/build-bridge.mjs` 用 `shell: true` 包一层 |
| `INSTALL_FAILED_USER_RESTRICTED` | MIUI 的「USB 安装」开关（不是 Android 原生设置） | 见上「未完成 ①」 |
| `adb push /data/local/tmp` 变成 `C:/Program Files/Git/...` | Git Bash 路径转换 | 命令前 `export MSYS_NO_PATHCONV=1` |

### 本轮修掉的三个真机问题（都是「默认配置在真机上静默失败」）

| 症状 | 根因 | 修法 |
|---|---|---|
| `node::Start returned rc=9`（1 ms 内返回，Node 从未跑） | 默认 `execArgv=["--no-verify-heap"]` —— **该 flag 在 Node 18 不存在**（V8 没有 `--verify-heap` 开关），Node 解析失败 → `uv_run` 返回 `UV_EBADF(9)` 被当退出码 | `NodeRuntimeOptions.execArgv` 默认改空；`docs/000` 同步注释 |
| `am start -e autorun 1` 不触发 autorun | `getBooleanExtra("autorun")` 遇到 String `"1"` 抛 `ClassCastException`（MIUI 15 上以 `W Bundle` warning 出现，分支被跳过） | 探针改 `getStringExtra` 判定（`"1"`/`"true"`） |
| `host.invoke` 报 `anb_host_call not found` | Android 的 **JNI 类加载器命名空间**把 `libnode_bridge.so`（`System.loadLibrary` 侧）与 Node `process.dlopen` 的 addon 隔离：`dlsym(RTLD_DEFAULT)` 搜不到对方符号；按绝对路径二次 `dlopen` 又被 linker 拒（`library ... not found`，实测） | ① addon 保留裸 soname dlopen 兜底（`DT_NEEDED libnode.so` 让 linker 把桥拉进同命名空间，多数场景直接命中）；② **双保险**：`NativeBridge.bridgeHandle()` 把引导件自身 handle 经 env `NODE_BRIDGE_BRIDGE_HANDLE` 注入，addon 加载后立即 `setBridge(handle)`，失败**当场抛错**不静默 |

### 探针 / 工具链顺手加固

- `selfcheck.js`：`EADDRINUSE` 时回退随机端口（`listen 0`）并**覆写** `<HOME>/real_port.txt`（同设备多探针/残留监听不再让整条链路静默失效）；`collect-evidence.sh` 读该文件自动 forward
- 探针 autorun 前先清 `files/node-bridge/payload/`（`.ready-<marker>` 缓存会让旧版本 JS 一直跑，改 marker `builtin-v1→v2` 只解决一次）
- host 侧门禁 `smoke-host.mjs --allow-page-align-4k` 保持全过
